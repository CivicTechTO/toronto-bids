# Waterfront Toronto public awarded contracts (#108)

`tb capture-waterfront-awards` captures the public monthly award publication and invokes the existing shared extraction model on uncached months. `--limit N` bounds new model requests; `--limit 0` captures all source text and replays existing cache without calling a model. Unfinished or unsupported months produce a nonzero exit code. The same capture runs as an isolated `waterfront awards` nightly step; partial failure still allows supplier rebuild and export.

Access is authorized as recorded in [the permission record](permissions/waterfront-toronto.md). Each run fetches only the award page. Full original response bytes are retained as `<DATA_DIR>/waterfront/<sha256>.html` before parsing, including responses whose layout cannot be understood. The parser requires the expected year/month hierarchy and independently checks that the visible year-body text survives normalization. It does not split supplier/title/value relationships using source-specific regexes.

`award_publication` preserves each visible text block, its publication month, source position, source URL, snapshot hash and verbatim method/attribution annotations. A block can be a heading-like context line, one award, several supplier/value pairs, or an incomplete publication. Its stable observation key hashes month, normalized literal text and occurrence among identical blocks; insertion or reordering of unrelated text cannot rekey it. Exact duplicate observations remain separate. Changed source text creates a new historical observation; absent observations are retained. These are archive keys, not native contract numbers or proven links to other procurements.

Months are the extraction unit so nested suppliers retain the title above them. Inputs and complete model results use the existing `extraction_cache` and unchanged shared prompt/version. Successful cache results are replayed deterministically. Prompt changes retain the existing global cache-invalidation implications.

`published_award` contains supported supplier/value claims linked to their source block. Supplier/value text must match exactly one block in that month; a literal extracted title can distinguish repeated pairs on different source lines. Construction-manager attribution is excluded when checking the recipient, so “awarded by X on behalf of Waterfront” cannot itself establish X as the winner. The original annotation stays on the block. Literal value matching retains the full surrounding source parenthetical: per-week rates and totals including construction trade packages keep their qualifiers. Numeric values require strict, complete numeric grouping; malformed amounts and qualified values stay NULL. No award day, bid, confidential value, native reference or funding fraction is invented.

`publication_extraction` makes pending extraction, unmatched money and unsupported supplier/value assignments visible. Every money token must be covered, including multiple awards within one text block. Supported claims are retained even when another claim in the month is refused. An incomplete refresh cannot delete prior claims. A fully verified refresh may replace derived claims for its observed blocks; source observations and cached extraction evidence are retained. Nonmonetary source context is exported verbatim; an `ok` verification is not a claim to have measured the publisher's total number of awards. Source omissions and model errors require review, rather than automatic correction or repeated requests for an unchanged cache input.

Procurement identity is namespaced to each supported publication claim, without fuzzy merges with portal/board records. Supplier dimension includes the accepted recipient names. JSON publishes `buyers[].award_publications`, `published_awards` and `publication_extractions`; CSV, Parquet and the generated schema include all three tables. These records remain separate from City-spine award totals. Waterfront is a partnered corporation; its Toronto funding share is not inferred from the three-government partnership.

The Bonfire, current-opportunities, vendor-of-record and ACAN portions of #108 remain outside this own-site awarded-contracts slice. In particular, an intended/contestable ACAN is not an awarded contract.
